When was the best time to buy and sell NVIDIA?

We answer it three ways, from a slow O(n²) search to a single O(n) pass, and measure how much the difference matters as the data grows. This is analysis of past prices, not prediction.

The problem

Given a list of daily prices, which single buy day and later sell day would have made the most money? Investors, analysts, and risk teams ask versions of this question constantly, and the data gets huge quickly.

The same problem is a classic: it reduces to finding the maximum subarray of daily price changes. We also summarize how daily returns are distributed.

Our solution

A Python tool that loads the price history, runs each algorithm on the same input, and reports the buy day, sell day, and profit. A benchmark script times every algorithm at growing input sizes, and a small app lets you try it yourself.

All three algorithms return the same answer, and our tests check that they agree.

Algorithms

Brute force (baseline)

Try every buy day and every later sell day and keep the best. Simple and obviously correct, which makes it the reference for our tests.

Divide and conquer (efficient)

Split the price changes in half. The best window is in the left half, the right half, or crosses the middle. Solve each side recursively and combine.

Kadane's linear scan (optimized)

Walk through the data once, tracking the best window ending at each day. One pass, constant extra memory.

Complexity

AlgorithmTimeExtra space
Brute forceO(n²)O(1)
Divide and conquerO(n log n)O(log n)
KadaneO(n)O(1)

The slow version is a poor algorithm choice, not a hard problem. The problem itself is easy, since one pass solves it. A harder related version, maximum profit with k transactions, needs dynamic programming.
